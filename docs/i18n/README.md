# Trilingual documentation

English | [中文](README.zh.md) | [Deutsch](README.de.md)

This repo's documentation is read by people and agents both inside and outside the company, so every document in scope is maintained in English, Simplified Chinese, and German. This page defines the pairing contract, checks, scope, and exclusions; [translation-rules.md](translation-rules.md) defines how to translate; [terminology.md](terminology.md) is the terminology source of truth. Routine agent work follows the lightweight path in [docs/AGENTS.md](../AGENTS.md); the extended [.agents/skills/dsh-translate-docs](../../.agents/skills/dsh-translate-docs/SKILL.md) workflow is available only through explicit user invocation.

## The pairing contract

- **All three languages carry equal authority.** A document may be authored and reviewed in any language first — a Chinese-first Agent Note is as legitimate as an English-first one — and the counterparts are translated from it. No file outranks the others; what binds them is that they must say the same thing.
- **A pair is four sibling files.** The English `foo.md`, the Chinese `foo.zh.md`, the German `foo.de.md`, and a consistency record `foo.i18n.yaml`, all in the same directory. No locale directories, no separate translation repo, no interleaved multilingual files. Pairs merge whole: a PR never lands one language without the other three files.
- **The consistency record.** `foo.i18n.yaml` holds the full git blob hash of each side as of the last time the sides were confirmed to say the same thing:

  ```yaml
  foo.md: 3f786850e387550fdab836ed7e6dc881de23001b
  foo.zh.md: 89e6c98d92887913cadf06b2adb97f26cde4849b
  foo.de.md: 1c0e5a2f8b3d4e7f9a0c6d8e2b4f7a1c3d5e9f0b
  ```

  Blob hashes, not commit hashes, so the record is computable for files edited in the same PR (`git hash-object foo.md`) and consistency is a pure content comparison. `--write` stores those snapshots in the local Git object database before recording them, including uncommitted working-tree contents, and pins every distinct stored blob under a content-addressed `refs/dsh/translation-pairing/snapshots/` ref so garbage collection cannot invalidate a recorded recovery pointer. The recorded hashes recover the exact last-confirmed text of every side, so an out-of-sync pair is updated by patching the counterpart minimally against the edited side's diff — never by re-translating whole files. Routine work makes that patch directly; when the user explicitly invokes the extended workflow, `pnpm run gen-translation-brief <pair>` can instead assemble the update at the narrowest safely aligned granularity and `--apply` can splice a code-fence-only change after structural validation. After bringing the pair back in line, `pnpm run verify-translation-pairing --write <pair>` re-records the hashes; that yaml diff is the reviewable act of confirming consistency, which is why `--write` requires naming the pairs you confirmed (`--write --all` is the explicit corpus-wide form).

  When two branches contain valid confirmations of the same pair, the installed `dsh-translation-pairing` Git merge driver composes a new record only if Git's default text merge succeeds for all three recorded owner-blob triplets and the merged pair retains its required switchers and structural signature. The Chinese and German files must retain their backlinks; an authored English source must retain its switcher, while a listed generated English source is exempt. A merge that mixes a two-hash record with a three-hash record is refused; the pair converts to a complete triplet before merging. Any structure the driver cannot verify remains an ordinary conflict; `pnpm run resolve-translation-pairing-conflicts` applies the same fail-closed operation to a merge that has already stopped, stages every safe pairing record, and exits unsuccessfully when other pairing conflicts remain. The [automatic pairing merges Agent Note](../../.agents/notes/implemented/process/2026-08-08-automatic-translation-pairing-merges.md) owns the mechanism and alternatives.
- **The pending-german conversion list.** Pairs that predate the German side carry a two-hash record (source and Chinese) and are listed by exact source path in the manifest's `pending-german` field. A pending pair must stay exactly bilingual: adding a `foo.de.md` file to a pending pair makes the gate require the complete in-sync trilingual triplet, and a stale `pending-german` entry for a converted pair is a gate error. Converting a pair is one PR that adds the German side, updates the switchers to the trilingual form, removes the manifest entry, and re-records the three hashes. The list is mechanically managed by the conversion PRs and ends empty; it is the sanctioned temporary exception to the no-rollout-list rule.
- **Language switcher.** The switcher line sits immediately after the H1 heading on every side: the English file reads `English | [中文](foo.zh.md) | [Deutsch](foo.de.md)`, the Chinese file `[English](foo.md) | 中文 | [Deutsch](foo.de.md)`, and the German file `[English](foo.md) | [中文](foo.zh.md) | Deutsch`. A pending pair keeps its two-link form. An authored English source must retain its switcher, while a listed generated English source is exempt, so it matches the generator output byte for byte. A README published outside GitHub (for example PyPI project metadata) may use the canonical `https://github.com/deepseek-ai/deepseek-harness/blob/master/<repository-path>` URL to the same pair files, so the switcher stays reachable at that location.
- **Structure mirrors the counterparts.** Heading depth and order, list kinds, ordered-list start numbers, list item counts, table row and column counts, semantic link targets with their query/fragment suffixes preserved verbatim, and byte-identical code blocks correspond one to one across all sides of the pair. A relative document link's target that belongs to the active corpus uses the `.md`, `.zh.md`, or `.de.md` path matching the source file's own locale. A missing counterpart inside the scope is a pair-completeness error, never a fallback; targets outside the scope keep their path. The full mirror rules live in [translation-rules.md](translation-rules.md). The existing Markdown gates apply to `.zh.md` and `.de.md` files unchanged (`verify-md-wrap`, `verify-md-links`); `verify-md-links` accepts a missing `.de.md` target while its English source is a pair source pending its German conversion, and judges the link once the file exists.

## The gate: verify-translation-pairing

`pnpm run verify-translation-pairing` (part of `doc-sync`, which contributors run locally against doc changes and CI runs in full) mechanically enforces this contract:

1. Every in-scope document carries a complete pair. README discovery is case-insensitive on the basename, so `missions/readme.md` is in scope like every other document root.
2. Every existing pair artifact is complete and in sync: the four files are present (the German side excepted for a pair listed in `pending-german`), each side's current blob hash equals its recorded value (editing any side without re-confirming the pair goes red), the Chinese and German sides and every authored English source carry a language switcher (except listed generated English sources), every ordinary relative document link uses the target locale of the source file's side, and the structural signatures agree in order: heading depth, byte-identical code blocks (info string and content), table row and column counts, list kinds, ordered-list start numbers, list item counts, and semantic link targets with their query/fragment suffixes preserved verbatim, excluding the switcher line. A pair listed in `pending-german` that carries a `foo.de.md` file must be a complete in-sync trilingual triplet; a stale list entry is a gate error.
3. Files listed as `excluded` carry no `.zh.md`, no `.de.md`, and no `.i18n.yaml`. Frozen Agent Notes under `.agents/notes/archived/` are outside this evolving gate; a dedicated validator requires their existing pair files to be complete and seals them.

Code gates that target source treat the exact `.zh.md` and `.de.md` fenced sequences as derived content of their suffix-less siblings, rather than recompiling the same code or registering it twice in the manifest. The sequences must agree in length, order, fence kind, and byte-exact body; otherwise both copies are checked independently and the pairing gate reports the structural mismatch.

`pnpm run verify-translation-pairing --list` prints the current pair state of every in-scope document (missing, pending, out-of-sync, or ok). It never fails; the missing, pending, and out-of-sync lines name the violations the ordinary check would reject.

`pnpm run verify-translation-pairing <pair...>` checks only the named pairs — any of the pair's four files (or its bare stem) names it — so the update loop validates its own pair in seconds without rescanning the corpus. `doc-sync` and CI run the unscoped corpus form; a scoped green light never replaces it at the PR level.

The practical rule the gate creates: **when a PR edits any side of a paired document, the same PR updates the counterpart files directly in one pass, terminology-guided, and re-records the pair with `--write <pair>`**, exactly like this repo's existing doc-sync rule for code and READMEs. A PR that leaves a pair out of sync goes red in CI.

The gate's limit is explicit: **a green gate means the documents' consistency at their current content is confirmed, not that the confirmation is correct.** It checks recorded hashes and Markdown structure; it cannot judge whether the sides say the same thing, whether the wording is right, the terminology sound, or the prose natural; review owns that part of the contract, per [translation-rules.md](translation-rules.md). A pair whose hashes were re-recorded but whose counterpart is sloppily translated passes the gate; it must not pass review.

## Scope and exclusions

**Scope**: the root `CONTRIBUTING.md`, `BRAND_GUIDELINES.md`, and `SAFETY.md` documents, every README outside vendored source, and every active document under `.agents/notes/**`, `docs/**`, and `python/**`. README matching is case-insensitive on the filename only, so new directories need no manifest change. Dependency directories, ignored build-output directories, and the frozen `.agents/notes/archived/` tree are excluded at discovery only; they are not evolving translation sources.

Generated English reference and image documentation with a reviewed Chinese counterpart follows the pairing rules. The generator remains the English source of truth; the freshness gate and the pairing gate each enforce their own constraint independently, and a regeneration that changes the English leaves the pair out of sync until the reviewed Chinese counterpart is updated and re-recorded. Generators that own both sides' output, such as the Cordis subsystem region generator, project the paired document path into each locale while keeping the remaining generated bytes identical. Generated English sources omit the language-switcher line that authored documents carry, because adding it would fail the generator's freshness check; the Chinese and German counterparts still link back to the English source. A generated page's Chinese counterpart may only reword self-referential generated-and-maintained prose that would no longer state the reviewed translation's facts if left literal; all technical content stays under the ordinary fidelity rules.

**Excluded** (never paired; the gate rejects a `.zh.md` or `.i18n.yaml` for them):

- [cordis-api/inherited.md](../cordis-api/inherited.md): the generated document has no reviewed Chinese counterpart, so the website projects the English source for both locales.
- `docs/AGENTS.md`, `.agents/notes/**/AGENTS.md`, and the `CLAUDE.md` instruction symlinks pointing at them: agent instructions, maintained in English only like the root `AGENTS.md`.
- `docs/i18n/terminology.md` and [style-samples.md](style-samples.md): both are themselves bilingual reference documents.
- [translation-prompt.md](translation-prompt.md): the automated translation pipeline's prompt template; its body enters model requests verbatim, and a paired translation would change pipeline behavior.
- [review-ownership/README.md](../../.github/review-ownership/README.md): the repository's internal review policy, maintained in English only.
- `.agents/notes/archived/`: frozen historical three-file pairs. [`verify-archived-agent-notes`](../../scripts/verify-archived-agent-notes.ts) validates their completeness and content seal; translation maintenance must never rewrite those files.

**Uniform requirement**: every in-scope document, current and future, merges as a complete trilingual pair. [scripts/translation-pairing.manifest.json](../../scripts/translation-pairing.manifest.json) carries the explicit exclusions and the `pending-german` conversion list only; there is no per-file rollout list, date cutoff, or README-only policy class.

## Division of labor

When a routine update touches a counterpart file, the responsible agent loads [terminology.md](terminology.md) first and updates directly in one pass; it does not invoke a translation skill, generate a briefing, run a separate translation-review pass, or delegate to a subagent. The extended [dsh-translate-docs](../../.agents/skills/dsh-translate-docs/SKILL.md) workflow retains those heavier mechanisms for explicit user invocation. The gate checks pair completeness, recorded hashes, the Chinese and German backlinks and the authored-source switcher (with the documented generated-source exception), and its documented structural signature. Review still owns translation quality, terminology, and structural requirements that the signature does not encode. The translation prompt and brief pipeline covers the English and Chinese directions; German documents are produced through the lightweight path. The prompt contract is executable: [scripts/translation-prompt.ts](../../scripts/translation-prompt.ts) renders the committed template (terminology injected; the template carries its own calibrated rules) into either direction and parses the three-section response, while `verify-translation-prompt` exercises both render directions and the checked-in example in `doc-sync`.
