# Agent Note: 将德语确立为一等的翻译配对语言
[English](2026-09-30-german-third-language-translation-pairing.md) | 中文 | [Deutsch](2026-09-30-german-third-language-translation-pairing.de.md)

Status: implemented


## Problem

文档语料库将每个英文源文件与一份中文翻译配对：门禁、清单、合并驱动器和标准恰好建模了两种语言。产品文档同样需要德语版本；一个不受门禁覆盖的可选德语姊妹文件会让第三种语言的结构、链接和同步状态得不到验证，同时却声称与另外两侧对等。

## Decision

德语是翻译配对契约中一等的第三种语言。一个配对由 `foo.md`、`foo.zh.md`、`foo.de.md` 和 `foo.i18n.yaml` 组成；三种语言具有同等权威，相互镜像结构，并保持生成区域在忽略区域路径后逐字节一致。一致性记录为已转换的配对保存三个 blob 哈希，为尚欠德语一侧的配对保存两个。

`verify-translation-pairing` 验证三语结构：每一侧的规范语言切换器、结构签名以及每一侧的链接区域。一侧链接自己的区域姊妹文件；只要推送仍未完成，`.de.md` 目标就通过其现存的配对源文件解析，因此已转换的文档可以引用德语一侧尚未写出的目标。已转换配对中过期的 `pending-german` 条目是门禁错误。

清单中的 `pending-german` 列表跟踪早于德语一侧而存在的配对。每一篇范围内的文档，无论现有还是未来，都作为完整的三语配对合并；该列表是经批准的临时例外，转换一个配对是一次变更：添加德语一侧、将切换器更新为三语形式、移除清单条目并重新记录三个哈希。配对合并驱动器拒绝将双哈希记录与三哈希记录混合的合并，因此转换永远不会针对过期记录静默组合。

德语一侧走轻量路径：由门禁验证的结构镜像，在语料库推送提供之前，不配备专用的提示/简报流水线、术语德语列或风格样例。[自动配对合并 Agent Note](2026-08-08-automatic-translation-pairing-merges.zh.md) 拥有合并机制且保持不变；它承载三语记录。

## Alternatives considered

**将德语添加为可选的、不受门禁约束的姊妹文件。** 一个不受检查的第三个文件会在门禁只认证两侧的情况下偏离配对的结构和链接；对等声称会超越验证。

**在本次变更中转换整个语料库。** 语料库涵盖数百个配对；一次性转换会将语言标准与大规模翻译工作耦合，并让标准的落地受制于翻译吞吐量。`pending-german` 列表改而跟踪推送。

**将德语排在英语和中文之下。** 配对契约赋予每种语言同等权威和结构镜像；一种衍生的第三种语言需要自己的同步方向和自己的失败面，相比现有模型没有任何收益。

## Consequences

- 每篇新的范围内文档在创建时就是完整三元组；缺少任何一侧的已转换配对会被门禁判为失败。
- 转换按配对通过 `pnpm run verify-translation-pairing --write` 记录；已转换配对的记录保存三个哈希，其 `pending-german` 条目被移除。
- 合并驱动器拒绝将双哈希记录与三哈希记录组合，因此并发的转换会显式地表现为冲突。
- `pending-german` 计数是语料库的剩余工作；`pnpm run verify-translation-pairing --list` 报告每篇范围内文档的当前状态。
- 提示/简报流水线、术语德语列和德语风格样例按[标准](../../../../docs/i18n/README.zh.md)所述推迟到语料库推送。
